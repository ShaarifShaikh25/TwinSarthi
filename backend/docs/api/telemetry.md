# Telemetry Ingestion & Data Honesty Specification

## 1. Data Honesty & Provenance Policy
Antarctica research operations mandate rigorous scientific integrity. To prevent deceptive reporting:
- Every ingested telemetry data point **must** explicitly identify its provenance source.
- Valid telemetry sources are:
  - `SIMULATED`: Generated by synthetic workload or physics-based simulation scripts.
  - `PUBLIC_HISTORICAL`: Derived from published scientific archives (e.g. NOAA, Antarctic meteorological records).
  - `PROTOTYPE_SENSOR`: Real-time edge readings from physical test hardware / microcontroller prototypes.
- **Strict Rule**: Ingested or displayed data is NEVER labelled as real unverified NCPOR operational telemetry unless verified by edge gateways.

---

## 2. Ingestion Pipeline Architecture

```
Sensors / Simulator / Microcontroller
             ↓ (MQTT or HTTP)
   FastAPI Ingestion Endpoint
             ↓
     Schema Validation
             ↓
  PostgreSQL / TimescaleDB
             ↓
   Digital Twin State Refresh
             ↓
  Rule-Based Alert Engine
             ↓
 WebSocket Broadcast (/ws/{station})
```

---

## 3. Endpoints

### 3.1 Ingest Telemetry
`POST /api/telemetry/ingest`

Accepts a single telemetry observation, verifies constraints, updates digital twin state, executes alert evaluation, and broadcasts real-time WebSocket events.

#### Request Body
```json
{
  "station_code": "MAITRI",
  "sensor_id": 1,
  "timestamp": "2026-09-29T12:00:00Z",
  "value": -24.5,
  "quality": "GOOD",
  "source": "SIMULATED"
}
```

#### Validation Rules:
1. `station_code` must match an existing registered station (`MAITRI`, `BHARATI`).
2. `sensor_id` must exist and be registered to the specified station.
3. `timestamp` must be a valid ISO 8601 string.
4. `quality` must be one of `GOOD`, `BAD`, `UNCERTAIN`, `UNKNOWN`.
5. `source` must be one of `SIMULATED`, `PUBLIC_HISTORICAL`, `PROTOTYPE_SENSOR`.

#### Response (`HTTP 200`)
```json
{
  "success": true,
  "data": {
    "id": 104,
    "sensor_id": 1,
    "value": -24.5,
    "quality": "GOOD",
    "source": "SIMULATED",
    "timestamp": "2026-09-29T12:00:00Z"
  }
}
```

### 3.2 List Telemetry
`GET /api/telemetry?limit=50`

Query recent telemetry points across all sensors and stations.

---

### 3.3 List Station Telemetry
`GET /api/telemetry/{station_id}?limit=50`

Query recent telemetry points specifically for `MAITRI` or `BHARATI`.
